## What is Test Documentation?

* Collection of artifacts created **before or during testing**.
* Helps in **estimating effort, coverage, tracking resources, execution progress, results**.
* Includes **planning, design, execution, and reporting documents**.

---

## Why Test Formality?

* Testing is not ad-hoc; it’s a **formal, documented activity**.
* Documentation makes planning, review, and execution **organized and verifiable**.
* Degree of formality depends on:

  1. Application type
  2. Standards followed
  3. Development process maturity

---

## Examples of Test Documentation

| Document                                   | Description                                           |
| ------------------------------------------ | ----------------------------------------------------- |
| **Test Policy**                            | High-level principles, methods, and goals of testing. |
| **Test Strategy**                          | Defines test levels/types for the project.            |
| **Test Plan**                              | Scope, approach, resources, schedule of testing.      |
| **Requirements Traceability Matrix (RTM)** | Links requirements to test cases.                     |
| **Test Scenario**                          | An event or functionality to be verified.             |
| **Test Case**                              | Inputs, conditions, expected outcomes for a scenario. |
| **Test Data**                              | Data used for executing test cases.                   |
| **Defect Report**                          | Documented flaws where software fails expectations.   |
| **Test Summary Report**                    | High-level summary of testing activities and results. |

---

## Best Practices

* Involve **QA team early** in the project.
* Keep documents **updated**, not static.
* Use **version control** for documents.
* Document only what is **useful** and needed.
* Use **standard templates** (Excel, Word).
* Store documents in a **central accessible location**.
* Provide **sufficient detail** to avoid ambiguity.

---

## Advantages

* Removes uncertainties and ambiguities.
* Provides **systematic approach**.
* Acts as **training material** for newcomers.
* Improves **transparency with clients**.
* Can be used for **marketing & sales** (shows mature process).
* Ensures **quality product delivery** within timelines.

---

## Disadvantages

* **Time-consuming** and may exceed value.
* Often poorly written.
* Keeping documents updated is tiring.
* Poor docs may cause **misunderstandings** with clients.

---

## Summary

* Test Documentation = all testing-related artifacts.
* Formality depends on application, standards, maturity.
* Includes docs like **Test Policy, Test Strategy, Test Plan, Test Case, RTM, Defect Report, Test Summary**.
* Helps reduce uncertainty, but can be **costly and time-heavy**.
