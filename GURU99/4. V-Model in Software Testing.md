✅ **V-Model in Software Testing**

---

**📌 What is V-Model?**
The **V-Model** (Verification and Validation Model) is a **software development model** where each development stage has a **corresponding testing stage**.
It’s called **V-Model** because the process flow looks like a **V** — development on the left, testing on the right.

---

### ✅ **How it Works**

| **Development Stage (Left Arm)** | **Testing Stage (Right Arm)** |
| -------------------------------- | ----------------------------- |
| 1️⃣ Requirements Analysis        | Acceptance Testing            |
| 2️⃣ System Design                | System Testing                |
| 3️⃣ High-Level Design            | Integration Testing           |
| 4️⃣ Low-Level Design             | Unit Testing                  |
| 5️⃣ Coding                       | —                             |

**Coding** is at the bottom where both arms meet.

---

### ✅ **Example**

| **Phase**             | **Example Activity**                                               |
| --------------------- | ------------------------------------------------------------------ |
| Requirements Analysis | Define what the app must do (e.g., users must log in).             |
| Acceptance Testing    | Test if final product meets user needs (login works as needed).    |
| System Design         | Plan entire system architecture.                                   |
| System Testing        | Test the complete integrated system (e.g., end-to-end login flow). |
| High-Level Design     | Define modules (e.g., frontend, backend).                          |
| Integration Testing   | Test how modules interact (frontend → backend API).                |
| Low-Level Design      | Design individual components (functions, classes).                 |
| Unit Testing          | Test individual units (e.g., login function).                      |

---

✅ **Key Point:**
**Each development activity has a matching test activity** — so defects are caught **early**, and the product aligns with requirements at each stage.
