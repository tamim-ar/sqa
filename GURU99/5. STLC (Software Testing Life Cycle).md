✅ **STLC (Software Testing Life Cycle)**

---

📌 **What is STLC?**
The **Software Testing Life Cycle (STLC)** is a **structured process** that defines **different phases** of testing — from planning to closure — to ensure software is thoroughly tested and meets quality standards.

---

### ✅ **Phases of STLC**

| **Phase**                      | **Description**                                                                 | **Example**                                                                              |
| ------------------------------ | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **1️⃣ Requirement Analysis**   | Understand what needs to be tested. Clarify requirements.                       | QA team reviews login requirements, checks for testability, raises queries.              |
| **2️⃣ Test Planning**          | Define scope, objectives, resources, timeline, tools, and risk management.      | Prepare Test Plan Document — decide who tests login, what tools to use, estimate effort. |
| **3️⃣ Test Case Development**  | Write detailed test cases and prepare test data.                                | Write test cases for valid/invalid login, password rules, error messages, etc.           |
| **4️⃣ Test Environment Setup** | Prepare hardware/software conditions where tests will run.                      | Deploy app on staging server, configure database, set up test accounts.                  |
| **5️⃣ Test Execution**         | Run test cases, log defects for any failed tests.                               | Execute login tests → if login fails with valid data, log a bug in Jira.                 |
| **6️⃣ Test Cycle Closure**     | Evaluate test completion, prepare test summary report, analyze lessons learned. | QA Lead prepares test closure report with defect stats, lessons for future projects.     |

---

### ✅ **Key Points**

* **STLC is iterative** — sometimes phases overlap.
* It ensures **testing is organized**, **traceable**, and **complete**.
* Focuses on **early defect detection**, better quality, and clear deliverables.
